# デプロイ検証記録

実施日: 2026-09-08（日本時間）。対象: `gather-quiz-dev`、AWS東京リージョン。

## 調査と反映

開始時、旧GatherQuizのLambda・RDS・CloudFront・ECRは存在しなかった。既存のRoute53ホストゾーンを利用し、無関係のリソースは変更していない。
旧ドキュメントに記載されたAPI IDや稼働状態は再利用せず、CloudFormationのOutputsから対象を取得した。
ZIP方式の最終構成で4スタックを新規構築し、その後の差分デプロイも確認した。

- 公開URL: https://dev.gather-quiz.june-yamamoto.com
- RDS: PostgreSQL 17.9、db.t4g.micro、Single-AZ、暗号化gp3 20GiB、非公開
- Lambda: Node.js 24、ARM64、ZIP（API 256MB／運用512MB）
- DBデータは検証用のものを削除し、検証後の3テーブルの件数はいずれも0件
- GitHub OIDCロールとリポジトリ変数`AWS_DEPLOY_ROLE_ARN`設定済み
- AWS向けワークフローは手動起動のみ。PRがmainへマージされた後にActionsから選択可能

## 実環境の動作確認

- HTTPSトップ画面、SPA直リンクとリロード、静的アセットのキャッシュ制御
- 存在しないAPIがHTMLに変換されずJSONエラーを返すこと
- 大会作成、主催者ログイン、参加者登録・ログイン、クイズ作成、問題ボード取得
- 署名付きURLによるPNGアップロードとCloudFront経由の画像取得
- 3テーブルにデータが入った状態のバックアップと、隔離スキーマへの復元・チェックサム一致・外部キー整合性
- テストデータ削除後、0件の実DBに対するバックアップからの復元と復元直前バックアップ作成
- Playwrightで公開サイトから大会作成画面へ遷移し、リロード後も表示でき、ブラウザ例外がないこと

検証スクリプトは`scripts/smoke.ts`、`scripts/browser-smoke.ts`。通常のActionsではデータを書かない`--read-only`を実行する。
今回の実環境構築・更新は作業環境から同じデプロイスクリプトを実行した。新ワークフロー自体の手動実行はmainへのマージ後に行う。

単一環境での参考値。依存インストール・テスト・Actionsキュー時間を含まない。

Dockerビルド・ECR push・全ファイル再転送・Invalidation待ちを通常の更新経路から除いた。

## 制約

ローカル検証はバックエンド41件、フロントエンド34件、インフラ4件、Playwright E2E 7件が成功。双方のlint・ビルドと運用スクリプトの型チェックも成功した。
ロックファイルに欠けていたRollupのOS別パッケージを同一バージョンで補完し、Windowsでのクリーンインストールとバックエンドテストを確認した。

バックアップは小規模データ用のgzip JSONで、画像・DDL・DBロールを含まない。上限や復元手順は[インフラ運用](インフラ運用.md)を参照。
負荷試験・Multi-AZ障害試験・Dev Container再構築は今回の動作確認に含まない。
公開サイトでの検証は専用の合成データを使用した。実利用者のデータを復元して上書きする試験は行っていない。
