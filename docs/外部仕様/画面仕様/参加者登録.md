# 参加者登録ページ

- URL: `/gather/tournaments/:id/register`
- 表示名: 1〜20文字（前後空白を除去）。大会内の重複を許可する。
- ID: 3〜20文字の半角英数字・ハイフン・アンダースコア。先頭は英数字。小文字に正規化し、大会内で一意とする。
- パスワード: 半角英数字4〜6文字。数字のみも許可する。
- 各項目に入力条件を常時表示し、表示名には文字数カウンターを表示する。パスワードは伏せ字で入力する。
- 登録成功時は表示名・IDを表示する。入力パスワードはstateから消去し、APIからも返さない。IDと設定したパスワードで再ログインする。
- 重複IDは409、入力不正は400。エラーをインライン表示し、入力を保持する。送信中の二重登録を防ぐ。
- 既存参加者はID未設定（NULL）のまま、従来の名前・パスワードでログインできる。旧名と競合する新IDは予約済みとして拒否する。

## パスワード保護

- ソルト16バイト、scrypt（N=32768,r=8,p=3）でハッシュ化して保存。比較はtimingSafeEqual。登録・ログイン・問題ボードからハッシュも平文も返さない。
- 参加者ごとにDBで試行回数を共有し、15分の窓で最大5回。成功時はリセット。上限超過は429で再試行案内を表示する。
- 存在しないIDとパスワード不一致は共通の401メッセージ。
- 既存の参加者パスワードは移行時に同じトランザクションでハッシュへ変換する。
- 短いパスワードの推測耐性には限界がある。現行の問題APIには本人確認のアクセス制御がなく、今回も認証セッションの導入は行わない。
- 参考: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。
