# チーム採点と順位発表

大会作成・概要編集ではチームを設定しない。開始前の主催者管理画面で、当日の参加チーム数（0～50）とチーム名を設定し、開始ボタンで確定する。0は採点管理なし。チーム名は空白を除き1～20文字、同名は不可。問題を作成する参加者とは独立しており、開始後はチーム構成を変更できない。開始に失敗した場合は入力を保持する。

採点を有効にした大会は、解答画面の「チームの正誤を設定」から全チームの正解・不正解を保存する。再保存はその問題の判定を置き換え、重複加点しない。正解はその問題の配点、不正解は0点。開催中の画面・APIには合計点や順位を公開しない。

全問題を開き、採点対象の全問題で全チームの判定を保存すると大会を終了できる。終了後は判定・問題を変更できず、再開もできない。採点なしの大会でも、全問題を開いてから終了する。

終了後の結果ページでは、下位から順番に順位を発表する。同点は同順位（1位・1位・3位）で同時に登場する。「すべての順位を表示」で演出を省略でき、OSの動きを減らす設定でも即時表示する。

## 既存データの移行

`0005_team_scoring/migration.sql` は既存テーブルに列を追加し、既存大会は採点なし、既存問題は未判定として保持する。初期SQLの差し替えではなく、運用Lambdaが既知の旧スキーマから順番に適用する。デプロイ前にバックアップと検証を行う。
