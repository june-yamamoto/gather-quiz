# 参加者ID・パスワード保護への移行

運用Lambdaのmigrateが既知の初期／0002スキーマからのみ、SQLとパスワードのscrypt変換を同一トランザクションで実行する。0001・0002の適用済みSQLは変更しない。

追加列はloginId（NULL可）、loginAttempts（初期値0）、loginWindowStart（NULL可）。表示名の一意索引をIDの一意索引へ置き換える。既存参加者の名前・UUID・問題を保持する。旧参加者は従来の名前でログインする。

SQLだけの直接適用は禁止。パスワード変換を含む運用Lambdaを使う。移行済みハッシュなら再適用しない。移行前にバックアップ・verifyを実行し、移行後もバックアップ・verifyを実行する。旧バックアップは新スキーマでは復元できないため保持する。

旧APIは平文比較を行うため、移行後に旧APIだけへロールバックしてはいけない。APIとDBを整合する状態へ戻す必要がある。通常デプロイは運用Lambda更新・移行・API更新の順で実行する。
